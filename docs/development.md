# Разработка и диагностика

Редактируйте файлы в [`college-journal`](../college-journal). После изменения скриптов перезагрузите расширение на странице управления расширениями, затем обновите вкладку колледжа. Для изменения формата данных проверьте, что дашборд и Excel читают ранее записанные журналы. Ключи вида `journal:<sha256>` уже используются существующими установками.

## Исследование живой страницы

1. Откройте журнал с доступом преподавателя и подождите загрузку. В DevTools на вкладке **Elements** найдите окно по заголовку, затем активную вкладку и обе половины нужной сетки.
2. В инспекторе выберите поле «Предмет». В **Console** можно проверить `$0.value` и, если инспектор находится в основном контексте страницы, `Ext.getCmp($0.id)`. Для этого шага достаточно убедиться, что компонент привязан к тому же полю.
3. Переключите один предмет вручную. Наблюдайте за выпадающим списком, маской, запросами на вкладке **Network** и заменой строк в сетке. Запросы полезны для понимания порядка событий. Текущий автосбор использует интерфейс сайта и читает уже отрисованную таблицу.
4. Сравните число строк слева и справа. Проследите путь от текстового заголовка занятия к скрытой ячейке через одинаковый класс `x-grid3-td-…`. Повторите после смены предмета, чтобы проверить, какие части разметки перерисовываются.

Локальный снимок DOM полезен для проверки селекторов, но для проверки ComboBox и задержек нужна живая страница либо имитация Ext JS. Для передачи примера разработчику достаточно обезличенных фрагментов разметки и временной последовательности событий. Файлы журнала, выгрузки с персональными данными, HAR и заголовки авторизации не добавляйте в репозиторий.

## Проверка перед изменением сборщика

| Сценарий | Ожидаемый результат |
| --- | --- |
| Список предметов появляется с задержкой | Прогресс ждёт список, предметы ещё не переключаются. |
| Название следующего предмета появилось до новой таблицы | Старая таблица не сохраняется под новым названием. |
| Есть три занятия в один день | Три записи сохраняются отдельно, если их ID различаются. |
| Журнал открывается повторно | Тот же предмет, период и состав обновляют существующую запись. |
| Сайт скрывает журнал за модальным окном или маской | Сборщик ждёт доступную таблицу. |
| Следующая таблица не появилась | После 60 секунд видна ошибка с названием предмета. Предыдущие записи доступны. |
| Нажата остановка | Сборщик прекращает обход и не открывает следующие предметы. |
| Дашборд открыт одновременно с журналом | Новая запись появляется автоматически, выбранный фильтр сохраняется. |
| Нажат экспорт | XLSX открывается, содержит три листа и те же записи. |

Для быстрой проверки синтаксиса при наличии Node.js запустите команды из корня репозитория.

```sh
for file in college-journal/{background,collector,journal-page,popup,dashboard,workbook}.js; do
  node --check "$file" || exit 1
done
```

## Типичные случаи

| Что видно | Что проверить |
| --- | --- |
| «Откройте вкладку “Журнал” нужной группы» | Открыто окно теоретических занятий, вкладка «Журнал» активна, видимое поле «Предмет» определено однозначно. |
| «Не удалось определить список предметов» | Компонент доступен в `MAIN`, ID поля разрешается через `Ext.getCmp`, у компонента есть Store и методы ComboBox, которые использует мост. |
| Список не загружается | Видны ли пункты по ручному клику, открыт ли список, дождался ли Store своих записей, равны ли числа записей и отрисованных элементов. |
| Таблица видна, но сбор остановился по тайм-ауту | Сравните отображаемый текст и значение ComboBox, состояние маски, обе половины сетки и факт замены правой строки. Сетка без студентов или схема, где обновляются только тексты в старых строках, может не пройти проверку 1.2.0. |
| Подсказка группы отсутствует или кажется неверной | Сверьте группу в самом журнале. Текущий способ использует выбранную подпись из выпадающего списка как ориентир. |
| После обновления кода кнопка работает со старым поведением | Перезагрузите расширение и целевую вкладку, затем заново запустите сбор. |

Ошибки вкладки колледжа и внутреннего дашборда смотрите в их DevTools. Для фонового сохранения используйте инспектор service worker со страницы расширений. Проверку записей проводите в том же профиле браузера, в котором запущен сбор.
