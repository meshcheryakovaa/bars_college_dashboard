# Дашборд журналов «Электронного колледжа»

Распаковываемое расширение Manifest V3, версия **1.10.1**. Собирает списки студентов и занятия из открытых журналов теоретических и практических занятий, сохраняет их в профиле браузера и показывает на отдельной вкладке. Для выбранной группы расширение может автоматически перебрать предметы. Также доступен ручной сбор и экспорт в Excel.

## Установка

1. Скачайте ZIP репозитория через **Code → Download ZIP** или клонируйте репозиторий.
2. Откройте `browser://extensions` в Яндекс Браузере, `chrome://extensions` в Chrome или `edge://extensions` в Edge.
3. Включите режим разработчика и выберите **«Загрузить распакованное расширение»**. Укажите [папку `college-journal`](college-journal), в которой лежит `manifest.json`. Сборка, npm и сервер для установки не требуются.

Если расширение уже установлено, замените файлы в существующей папке, нажмите **«Обновить»** на странице расширений и перезагрузите вкладку колледжа перед новым запуском. Обновление той же установки позволяет использовать ранее собранные записи.

## Справочник и выбор групп

Откройте дашборд из меню расширения на вкладке колледжа. Раскройте список групп на сайте и нажмите **«Считать список групп»** на дашборде. В разделе **«Группы»** поставьте отметки **«Для анализа»**. Фильтр **«Только отмеченные группы»** действует на все таблицы и счётчики дашборда. Настройки сохраняются после закрытия вкладки.

Нажмите **«Собрать отмеченные группы в обоих журналах»**. Расширение откроет теоретический журнал и пройдёт отмеченные группы текущего сайта и учебного периода, затем откроет практический журнал и повторит обход. При запуске активируется вкладка колледжа. Дашборд показывает текущий журнал, группу, дисциплину и число пройденных сочетаний журнала и группы. Если сайт не открыл нужную группу автоматически, выберите указанную группу вручную в той же вкладке.

Чтобы заполнить дисциплины и состав студентов отдельной группы, откройте нужную группу на сайте и нажмите **«Собрать открытую группу»** на дашборде. Названия дисциплин сохраняются из загруженного списка сразу. Студенты добавляются по мере чтения каждого журнала.

Команда **«Сохранить БД в папку расширения»** предлагает выбрать файл `catalog-db.json`. Если браузер выдал разрешение, файл обновляется при изменениях, пока открыт дашборд. Для разового сохранения доступна кнопка **«Скачать БД»**. Файл содержит Ф. И. О. и ID студентов и исключён из Git.

## Даты и очистка базы

В дашборде выберите **«С»** и **«По»**. По умолчанию используется период с **01.09.2026** по сегодняшнюю дату. Автосбор применяет диапазон в каждом журнале до выбора группы и дисциплины. Для ручной работы нажмите **«Применить даты в журнале»**, дождитесь подтверждения и затем выбирайте группу и дисциплину. Собранные журналы накапливаются независимо от смены диапазона.

**«Очистить базу дашборда»** после подтверждения удаляет локальные журналы, справочники и отметки групп. Очистка останавливает текущий сбор. Диапазон дат сохраняется. Если к дашборду подключён файл `catalog-db.json` с доступом на запись, в него будет записан пустой справочник.

## Сбор для одной группы

1. Войдите в «Электронный колледж» обычным способом. Откройте нужный журнал, примените диапазон дат, выберите группу и оставьте активной вкладку **«Журнал»**.
2. В меню расширения нажмите **«Собрать журналы группы»**. Группу выбирает пользователь, предметы этой группы перебирает расширение. Во время обхода оставьте окно журнала открытым.
3. В меню можно увидеть текущий предмет, прогресс и причину остановки. Кнопка **«Остановить автосбор»** прекращает дальнейший обход. При ошибке уже собранные записи доступны.
4. Нажмите **«Открыть дашборд»**. В нём есть таблицы журналов, студентов и занятий, поиск и фильтр по журналу. Таблицы обновляются после сохранения каждой записи. **«Скачать Excel»** выгружает те же данные в книгу с тремя листами.

Для ручного обхода нажмите **«Запустить ручной сбор»** и последовательно открывайте журналы в той же вкладке. После полной перезагрузки страницы сбор нужно запустить заново.

Данные хранятся локально в профиле браузера. Дашборд получает уже сохранённые записи. Выгрузка может содержать Ф. И. О. и ID студентов, поэтому примеры в документации используют вымышленные значения.

## Запись ручного сценария

Для диагностики выбора журнала, дат, группы и предмета установите отдельное [тестовое расширение](journal-inspector/README.md). Оно формирует пошаговый JSON-отчёт по действиям на вкладке.


### План заполнения журнала

Раздел «Заполнение журнала» в дашборде сохраняет номера тем КТП по каждой дате/ID занятия, поддерживает планирование оценок «3» и учёт подтверждённых вручную этапов «КТП → оценки → закрытие». Переходы «КТП», «Оценки», «Закрытие» находят столбец на странице БАРС по ID при точном совпадении журнала. **В версии 1.7.0 кнопки каждой строки вызывают штатные действия БАРС.** Если сохранение или его результат не удаётся проверить, отметка не проставляется автоматически. Подробности: [инструкция](college-journal/README.md).


### Запись в БАРС (версия 1.7.0)

К каждой строке добавлены кнопки **«Сверить»**, **«Привязать КТП»**, **«Всем „3“»**, **«Закрыть занятие»**. Для запросов используется штатный интерфейс Ext JS страницы; выбор занятия выполняется по ID, дате, группе, дисциплине и виду журнала. Перед изменениями появляется подтверждение. При неоднозначности КТП или оценочной колонки выполнение останавливается. Проставленные вручную статусы сохраняются отдельно от состояния БАРС. **Живое тестирование авторизованного сайта ещё требуется.**


**Исправление 1.7.1:** перед привязкой КТП и закрытием занятия расширение выбирает **«Пос» («Посещаемость»)** в нижней строке заголовков именно нужного занятия. Соответствие определяется по ID занятия, поэтому одинаковые даты не смешиваются. Проверка: `node tests/lesson-attendance-header.cjs`.


## Версия 1.8.0 — пакетное заполнение КТП

Команды занятия работают в фоновой вкладке колледжа без переключения из дашборда. Добавлена кнопка **«Привязать все темы КТП по очереди»**, прогресс и остановка. Предварительная проверка номера КТП, последовательное выполнение, сохранение результатов и защита от повторной записи. Для фоновой вкладки требуется разрешение `https://college.72to.ru/*`. Отправленные привязки необходимо отдельно подтвердить в БАРС.


## Версия 1.9.0 — массовое оценивание и закрытие

В разделе **«Заполнение журнала»** появились команды **«Всем „3“ по всем занятиям»** и **«Закрыть все занятия»**. Они применяются к выбранному журналу, выполняются последовательно в фоновой вкладке БАРС без изменения активной вкладки, показывают прогресс и поддерживают остановку. Тройки заполняют только пустые оценки, затем проверяются повторным чтением. Массовое закрытие предварительно требует подтверждённые КТП и оценки для каждого незакрытого занятия. При ошибке или неподтверждённом результате очередь останавливается. Подробности: [инструкция](college-journal/README.md).


## Исправление 1.9.1 — подтверждение закрытия с задержкой

В БАРС состояние занятия обновляется с задержкой на одно закрытие. Теперь пакетный режим закрывает A, затем B, проверяет A, затем закрывает C и проверяет B. Последнее занятие проверяется после принудительного обновления таблицы. Если подтверждения нет, оно сохраняется как ожидающее проверки, а не закрывается повторно. Для таких строк добавлена кнопка **«Проверить закрытие»** без повторной записи на сервер. Можно продолжить единственное ранее отправленное, но неподтверждённое закрытие после следующего занятия.


## Версия 1.10.0 — заполнить журнал по датам

В разделе **«Заполнение журнала»** введите одно число в поле **«Начальный № темы КТП»**. Остальные темы автоматически назначаются с шагом **+1 в порядке дат** (при совпадении даты — по номеру занятия). Можно подтвердить заполнение отдельно кнопкой **«Расставить КТП +1 по датам»**. Уже выполненные занятия с другим номером не перезаписываются. Кнопка **«ЗАПОЛНИТЬ ЖУРНАЛ ПО ДАТАМ»** обрабатывает каждую дату последовательно: привязывает КТП, ставит «3» в пустые оценки, закрывает занятие, нажимает «Обновить» и проверяет. Из-за задержки БАРС закрытие предыдущего занятия может окончательно подтвердиться после следующего. Ошибки и неопределённые предыдущие операции блокируют автоматический повтор. [Подробная инструкция](college-journal/README.md).


## Исправление 1.10.1 — ошибка `grading is not defined`

Устранена ошибка в обработчике «Привязать все темы КТП»: в код пакетной привязки ошибочно попала переменная `grading` из сценария массового закрытия. Обработчик закрытия вновь направляет выполнение в алгоритм отложенной проверки. Для всех пакетных кнопок добавлены сообщения об ошибках в самом дашборде. Добавлен регрессионный тест `tests/lesson-workflow-routing.cjs`.
